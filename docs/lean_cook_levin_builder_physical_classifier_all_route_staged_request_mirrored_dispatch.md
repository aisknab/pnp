# Lean Cook-Levin all-route staged-request mirrored dispatch

M227 connects every verifier-derived post-header classifier route to one
literal request relay and reflected dispatcher. The source is
`lean/PNP/Concrete/CookLevinBuilderPhysicalClassifierAllRouteStagedRequestMirroredDispatch.lean`.

## What is constructed

M226's fixed 720-rule wrapper sends every body coordinate and the unique
`Finish` coordinate to one continuation-ready classifier state. M227 runs that
same terminal-joined classifier on a protected workspace containing one
canonical optional-token request behind a blank sentinel. It then reuses
M225's fixed 14-rule scanner to cross the exact blank-free classifier prefix,
validate the staged request, and form the spatial mirror of M217's dispatcher
entry. M217's reflected fixed 64-rule dispatcher appends the selected body
token, emits nothing for padding, or accepts `Finish`.

The complete collision-free composition has 816 rules. For every coordinate in
the complete post-header schedule, Lean proves:

- the typed route is a body coordinate or the unique `Finish`, never
  out-of-range;
- the canonical optional request is one of all five physical request symbols;
- body and `Finish` terminal tapes have the exact append geometry and a
  blank-free classifier prefix needed by the common relay;
- the relay reaches the exact mirrored dispatcher entry;
- the dispatcher reaches the exact next canonical emitted prefix;
- exact work-machine and six-for-one compiled traces;
- nonhalting one work step before completion;
- collision freedom and distinct terminal states; and
- one verifier-input-size polynomial bound for the complete run.

The 65 public declarations have a complete kernel axiom transcript: 23 have an
empty closure, four use only `propext`, and 38 use only `propext` and
`Quot.sound`. None uses `Classical.choice` or a project-specific axiom.

## Claim boundary

The canonical request is still staged on the protected initial tape; M227 does
not synthesize it from the raw classifier state. It does not connect the final
configuration for one coordinate to the initial configuration for its
successor, implement one repeated raw-machine builder loop, prove complete
builder `FunctionProgram.RawRefinement`, package the Cook-Levin
`PolynomialReduction`, establish concrete NP-hardness or NP-completeness, put
`CNFSAT` in `P`, close a fixed checkpoint or global gate, create the eligible
root theorem, or prove `P = NP`.
