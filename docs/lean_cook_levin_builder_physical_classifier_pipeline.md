# Lean Cook-Levin physical classifier pipeline

M220 replaces the remaining value-level handoff across the pre-request
classifier stages with one fixed literal work machine. For every canonical
post-header coordinate and arbitrary protected builder workspace, the machine
physically composes:

1. M213's 351-rule post-header tape bridge;
2. M211's 99-rule raw quotient/remainder divider;
3. M214's 180-rule post-divider classifier bridge; and
4. M209's 54-rule body-versus-`Finish` comparator.

Three total nine-symbol launch tables connect those four components. The
resulting table therefore has exactly 711 rules. Its determinism proof is
compositional: each component's checked pairwise-query theorem and absence of
rules at intermediate accept states feed `WorkMachineChain`, rather than
recomputing every pair in the combined table.

## Exact all-coordinate interface

The endpoint accepts only a concrete `VerifierTableauProblem`. It quantifies
internally over every index in the verifier-derived post-header body-slot
range and every workspace. The index selects the exact equal or greater M213
entry tape; no comparison result, quotient, remainder, route, trace, table,
certificate, or verdict is supplied by the caller.

For each index, Lean proves all three tape handoffs, the exact work trace of
the 711-rule machine, the exact six-transitions-per-work-step compiled trace,
and nonhalting with one work step less. The final physical state agrees with
M214's typed route semantics: body coordinates accept, the unique `Finish`
coordinate rejects, and an out-of-range route is impossible.

The compiled work is bounded by M214's existing verifier-derived source-size
polynomial plus 18 transitions, exactly accounting for the three new
WorkMachineChain launches. This is a uniform encoded-input-size polynomial;
it is not an exhaustive finite search or a bound derived from supplied data.

## Claim boundary

M220 closes the suffix-preserving physical classifier pipeline preceding raw
request generation. It does not derive body-token or padding request symbols,
connect those requests to M217's dispatcher, iterate successive coordinates
inside one literal raw-machine loop, construct the complete raw formula
builder, prove builder `FunctionProgram.RawRefinement`, or package the
Cook-Levin `PolynomialReduction`. It does not prove CNFSAT NP-hardness,
CNFSAT in P, any global gate, the eligible root theorem, or `P = NP`.
