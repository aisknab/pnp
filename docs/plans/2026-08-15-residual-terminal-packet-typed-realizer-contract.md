# Residual terminal Packet typed-realizer contract plan

## Legacy anchor

Pinned manuscript Section 14, `Selector realization`, names the obligations
`realizerBotTyped` and `realizerBotOnlyHNBUDBlockedOrLowerRank`. A faithful
Packet selector may fail to return a checked gain only by naming an active
same-or-lower-rank hereditary blocker, an active same-or-lower-rank budget
blocker, or a faithful strictly lower-rank selector. The current checked
unit-charge realizer instead ends in untyped supplied-family validator silence.

## Unbounded abstraction

Work over an arbitrary selector type, arbitrary finite selector list, arbitrary
positive finite rank carrier, arbitrary executable faithfulness predicate, and
arbitrary executable HN and budget activity tables. Ranks are canonical finite
indices in the supplied rank carrier. A realizer claim contains data only: either
one unit-charge replacement blueprint or one of the three public typed bot
constructors. It contains no proof of validity, gain, blocker activity,
faithfulness, or rank decrease.

The generic validator is then instantiated over every canonical handle of an
arbitrary finite explicit grouped BN6 family. This remains input-relative: it
does not identify the finite indices with the manuscript's rank tuple or derive
any table from a terminal candidate.

## Exact theorem boundary

The executable claim checker must accept exactly when:

- a gain claim's unit-charge blueprint passes the existing exact-occurrence and
  semantic-equivalence validator;
- an HN bot names an active rank no greater than the current selector rank;
- a budget bot names an active rank no greater than the current selector rank;
  or
- a seed bot names a selector whose faithfulness predicate is true and whose
  rank is strictly smaller than the current selector rank.

The faithful-table checker must inspect every selector in an arbitrary finite
list and reject any faithful selector whose claim fails. Acceptance must prove,
for each faithful selector in that list, a disjunction consisting only of a
genuine charge-derived `StrictEquivalentGain` or one of the three typed blocker
facts above. The canonical-family theorem must cover every input-relative Packet
handle through the existing exhaustive handle enumeration.

## Remaining downstream blockers

The selector family, rank assignment, faithfulness predicate, realizer claims,
HN activity table, and budget activity table remain explicit inputs. The
milestone does not construct blueprints or blockers from terminal data, prove
manuscript selector faithfulness or compatibility, encode the manuscript rank
tuple, establish blocker semantics or HB acyclicity, derive complete selector
coverage, prove polynomial enumeration or runtime, reinterpret an invalid row as
a typed bot, or establish global selector silence. It does not prove PkgC route
silence, unconditional ZeroSlack, PCCMin, `CNFSAT ∈ P`, remove a project axiom,
or prove `P = NP`.

## Required evidence

- A Lean theorem module with data-only gain/HN/budget/lower-seed claims, exact
  Boolean specifications, faithful-list validation, and canonical-family
  coverage.
- A source-derived axiom audit and generic regression covering all four accepted
  branches plus inactive, rank-increasing, nonfaithful, malformed-blueprint, and
  faithful-static-reject cases.
- A hostile JavaScript audit rejecting proof-bearing claim fields, untyped bot
  constructors, non-strict lower-seed ranks, unchecked activity or faithfulness,
  omitted canonical-handle coverage, fixed selector/rank bounds, and ZeroSlack or
  polynomial-runtime overclaims.
- Synchronized theorem inventory, publication map, status payloads, report,
  documentation, and durable read-only workflow checks.
