# Residual terminal Packet selector-faithfulness routing milestone

## Objective

Reconstruct the executable first-failure boundary shared by the pinned
manuscript's Pair packet seed, Balanced-triple seed, Full-span spine seed, and
patched BCEL seed theorems.  For every canonical handle in an arbitrary finite
grouped BN6 family, the selected source payload must either pass every named
faithfulness field at the handle's exact finite rank or expose the first typed
route.  A route-clear positive Packet conclusion must therefore supply a
computed faithful handle, and that handle must contradict the already checked
HB selector-silence induction.

## Legacy anchor and dependency edge

The legacy anchor is the Packet section immediately before Package R and HB:

- `Pair packet seed`;
- `Balanced-triple seed`;
- `Full-span spine seed`; and
- `BCEL seed, patched`.

The exact dependency edge is:

```text
positive BN6 Packet
  + executable Packet payload route clearance
  + checked binding to the HB faithfulness table
  -> faithful canonical selector
  -> contradiction with executable HB selector silence
```

This is the nearest missing edge from the earned Packet/HB reconstruction to
the unearned `PNP.Main.zero_slack_complete` publication row.  It is quantified
over arbitrary finite grouped families and handle universes, rather than a
fixed carrier, rank prefix, or packet fixture.

## Checked interface

1. Define a closed typed route enumeration for the manuscript's first-failure
   fields: colour, frontier, charge, obligation, activation, direction,
   budget, rank, exact route, and strict descent.
2. Define a data-only Packet selector payload carrying Boolean results for the
   semantic fields and one finite rank tag.  Define the first route by a fixed
   fail-closed priority order; do not accept proof fields or a caller-supplied
   `faithful` flag.
3. Prove that checker acceptance is exactly the conjunction of every field
   check and equality of the payload rank with the canonical handle rank.
   Accepted payloads must expose no route, and every exposed typed route must
   prove checker rejection.
4. Reuse the existing canonical handle, source-cell, and first-positive-payload
   realization.  Exhaustively scan every canonical handle and prove the
   route-clear Boolean recognizes computed payload faithfulness for every row.
5. Check, for every canonical handle, that the existing HB environment's
   `faithful` Boolean equals the computed payload result.  Prove exact checker
   equivalence so an arbitrary faithfulness table cannot be accepted silently.
6. Prove that every existing `TerminalBN6PacketConclusion` supplies at least
   one canonical handle.  Route clearance plus accepted faithfulness binding
   then gives a handle whose HB faithfulness bit is true.
7. Compose that witness with
   `TerminalPacketTypedRealizerTable.noFaithful_of_selectorSilent`.  Accepted
   Packet route clearance, faithfulness binding, selector silence, and HB
   active-dependency closure must be inconsistent.

## Regression and hostile evidence

- Cover handle existence across pair, balanced-triple, and full-span branches
  over arbitrary finite input data.
- Reject each typed payload-field mutation and a mismatched rank tag, checking
  exact first-failure priority.
- Reject a supplied HB faithfulness table that disagrees with computed payload
  faithfulness.
- Exercise Packet-handle existence, computed faithful witness extraction, and
  the Packet-versus-HB contradiction.
- Derive the axiom transcript from every public declaration in the module and
  forbid assumptions, `sorry`, hidden faithfulness flags, fixed carrier/rank
  bounds, project axioms, and theorem-name overclaims.
- Pin only the reviewed public theorems in the compiled inventory and formal
  publication map.

## Conservative claim boundary

The grouped BN6 family, exact grouping, atom payloads, field-check Booleans,
finite rank tags, realizer claims, blocker activity, dependency rows, and
finite-to-exact rank map remain explicit inputs.  This milestone checks those
finite data exhaustively but does not derive them from a terminal candidate or
prove that a field Boolean has the manuscript's external semantics.  It does
not construct positive residual slack, SaturatePositive, BCELReady, the grouped
BN6 family, or the no-lower ledger.  It does not prove unconditional ZeroSlack,
`PNP.Main.zero_slack_complete`, PCCMin exactness, encoded-size or polynomial
runtime bounds, SAT in P, remove a project assumption, or prove `P = NP`.

## Remaining downstream blockers

After this milestone, the residual-band row still requires:

1. an executable positive-residual/no-lower route that constructs the
   route-clear grouped BN6 Packet input rather than accepting it as data;
2. complete ZeroSlack closure and its encoded-size proof;
3. PCCMin loop exactness and polynomial runtime/certificate bounds; and
4. the concrete root theorem and final axiom audit.
