# M170 terminal-derived HResolve support resolver

## Evidence-led selection

M169 established a sound and complete route ledger only relative to an
arbitrary supplied finite family and arbitrary supplied decidable exact, gain,
and blocker predicates. The formal publication map still has two unearned
global rows, and the residual-band minimizer, ZeroSlack, polynomial bounds,
concrete SAT, and root theorem remain active blockers. The next useful bounded
step is therefore to remove the supplied-family and supplied-constructive-
predicate boundary on an existing terminal-derived universe without claiming
the missing polynomial algorithm.

## Target

For every finite direct-wire candidate and its candidate-derived terminal
saturation model:

1. construct the complete canonical terminal support-seed family;
2. prove the family duplicate-free and prove every canonical selected seed is
   present;
3. saturate and extract each seed through the candidate-derived dependency
   system;
4. compute exact versus gain from the extracted implementation's residual
   slack;
5. reflect exact into semantic minimality and gain into a strict equivalent
   implementation; and
6. prove every governed seed has one of those two constructive routes.

The named endpoint is
`PNP.DirectWire.terminal_hresolve_support_resolver_constructive_complete`.

## Claim boundary

The construction uses exhaustive terminal subset enumeration and exhaustive
reference minimization. It is not a polynomial HN/BWL or HResolve algorithm.
HN grammar, ParseOrExit, H-disjointness, NoHereditary blockers, BudgetResolve,
the complete no-lower ledger, unconditional ZeroSlack, PCCMin runtime, SAT in
P, the publication root, and all project-axiom removal remain outside M170.

## Required evidence

- root import and compiled theorem-inventory inclusion;
- explicit axiom transcript for every public declaration;
- exact and gain regression fixtures, including a redundant-gate gain case;
- hostile mutations for supplied-family substitution, arbitrary saturation,
  altered slack predicates, caller route predicates, fixed bounds, assumptions,
  and global overclaims;
- publication-map and formal-status rows with reviewed kernel fingerprints;
- current reconstruction, audit, pipeline, terminology, README, and canonical
  report documentation; and
- durable CI and aggregate-verifier coverage.

Run the focused module build, axiom audit, regression, and hostile audit first.
After the source and claim boundary stabilize, regenerate the compiled theorem
inventory, publication payloads, and canonical report, then run the complete
