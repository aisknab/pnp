# M172 terminal budget no-lower ledger

## Evidence-led selection

M171 returns the first feasible canonical terminal support with exact or gain
evidence, or a strong global `NoBudget` result. That is a useful resolver but
does not exclude a strict gain elsewhere in the same budget-feasible support
universe. The declared residual dependency order still requires a complete
no-lower composition. The next bounded step is therefore an exhaustive route
ledger over every canonical support, with an executable acceptance condition
that rules out every feasible gain.

## Target

For every finite direct-wire candidate, candidate-derived saturation model,
and supplied pair of natural resource caps:

1. classify every canonical support as exact, strict gain, or `NoBudget` using
   the existing recomputed envelope and actual residual slack;
2. materialize a complete route ledger over the canonical support universe;
3. prove every row comes from that universe and every governed seed has its
   computed row;
4. check exhaustively that no route is a strict gain;
5. reflect acceptance to semantic minimality of every budget-feasible support;
   and
6. exclude every governed, feasible strict-equivalent-gain witness.

The named endpoint is
`PNP.DirectWire.terminal_budget_no_lower_ledger_excludes_feasible_gain`.

## Claim boundary

The resource caps remain explicit inputs. Subset enumeration,
candidate-derived saturation, and reference minimization are exhaustive and
may be exponential. M172 closes only the finite terminal-derived budget branch
of the remaining no-lower ledger. It is not the manuscript's HN/BUD grammar,
BWL or budget-envelope dynamic program, blocker dependency semantics,
polynomial BudgetResolve, Packet or full no-lower composition, unconditional
ZeroSlack, PCCMin exactness or runtime, concrete SAT, the root theorem, or any
project-axiom removal.
