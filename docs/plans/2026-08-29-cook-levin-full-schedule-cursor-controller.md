# Cook-Levin full-schedule cursor-controller milestone

## Legacy anchor

The concrete Cook-Levin route already has an exact rectangular token schedule,
pointwise direct decoders, and a semantic cursor whose one-step law agrees with
that schedule. The literal builder route separately emits the complete width
header and many checked fixed prefixes, padding blocks, and width-dependent
opportunities. Its authoritative status still records the general dynamic
cursor, complete formula builder, raw refinement, and packaged polynomial
reduction as absent.

The fixed-prefix sequence cannot be the long-term construction architecture:
adding another named schedule position does not establish a uniform builder.
M208 therefore returns to the first unresolved general control edge. It builds
one literal all-input controller that traverses the complete body schedule by
an input-dependent count and materializes the unique terminal token cursor.

## Unbounded abstraction

The theorem ranges over every `PolynomialTimeVerifier`, every raw input
bitstring, both tableau input modes, and the resulting arbitrary polynomial
formula dimensions. The controller count is the full rectangular clause-token
body size plus the final `Finish` opportunity. No fixed constraint, clause,
literal, cursor coordinate, input length, tableau width, or schedule slot
appears in the public theorem interface.

## Exact theorem boundary

Define verifier-owned `NatPolynomial`s for:

1. the first body token coordinate immediately after the padded width header;
2. the complete body token-opportunity count; and
3. the terminal token coordinate.

Prove that their evaluations are exactly the corresponding canonical schedule
coordinates. Extend the token-cursor specification with a fuelled run and prove
exact prefix, complete-body, full-run, terminal, and excess-fuel laws. In
particular, the complete body run must return the literal suffix of
`formulaTokenSchedule`, end at `formulaTokenSlotCountDirect`, and emit the
canonical formula-body token stream after padding is removed.

Construct one literal work machine by composing:

1. the existing all-input complete-header builder;
2. a structurally generated unary evaluator for the complete body count;
3. the existing fixed countdown controller, looping once for every body token
   opportunity; and
4. a structurally generated unary evaluator for the terminal cursor.

For every raw input, prove an exact trace from the ordinary raw start tape to a
halted endpoint that preserves the source and checked width-header output,
consumes exactly the computed body opportunity count, and contains the exact
terminal token coordinate. Derive a single external `NatPolynomial` raw-time
bound, compiled execution and non-timeout results, collision-free rule tables,
and fail-closed malformed and one-step-short boundaries. No count, cursor,
outcome, schedule list, runtime proof, or success flag may be supplied by the
caller.

The public endpoint is
`cook_levin_full_schedule_cursor_controller_checked_complete`.

## Downstream blockers

M208 supplies uniform schedule-loop control only. The raw controller does not
yet decode an arbitrary token opportunity, dispatch padding versus `F`, `T`,
`Sep`, or `Finish`, append the decoded token, or feed the terminal odd zero bit.
It therefore does not set
`leanConcreteCookLevinBuilderDynamicCursorFormalized`,
`leanConcreteCookLevinFormulaBuilderFormalized`,
`leanConcreteCookLevinBuilderRawRefinementFormalized`, or
`leanConcreteCookLevinBuilderPolynomialReductionFormalized` to true.

The next load-bearing Cook-Levin edge is a raw arbitrary-slot decoder tied to
`formulaTokenSlotDirect`; after that, the decoder, appenders, controller, and
final bit can be closed into the complete builder and packaged reduction.
Concrete CNF-SAT NP-hardness, a deterministic CNF-SAT decider, residual-band
minimization, unconditional ZeroSlack, polynomial PCCMin, the eligible root
theorem, and the publication gate remain open.
