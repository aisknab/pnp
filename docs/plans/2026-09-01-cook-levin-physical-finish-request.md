## Selection rationale

M218 composes the fixed M217 request dispatcher over every canonical
post-header coordinate, but each request is still constructed in Lean.  The
first safe literal request-generation branch is the unique `Finish`
coordinate.  M214 already proves that this coordinate reaches the equal
terminal state of the physical quotient-versus-clause-count comparator, and
M217 already consumes a tape-resident `Finish` request.  M219 connects those
two checked interfaces without accepting a supplied route, request, or token.

## Unbounded abstraction

Range over every concrete polynomial-time verifier problem and arbitrary
classifier exterior workspace.  Preserve the canonical builder workspace as
a suffix beyond the comparator's protected end marker.  A fixed writer changes
the exact equal-terminal end marker into the physical `Finish` request symbol,
then one fixed composed machine enters M217 and appends the final token.

The construction must retain the exact M214 in-range classifier theorem for
the problem-derived final coordinate, prove the right-suffix comparator trace,
the request-writing transition, the complete composed work and compiled
traces, one-step-short nonhalting, a collision-free fixed rule table, and one
verifier-derived source-size polynomial bound.

M219 covers only the unique canonical `Finish` branch.  It does not derive
padding or body-token requests from raw clause and token coordinates, preserve
the builder suffix through every preceding physical classifier stage, connect

percent uncertainty range.  Formal artefact coverage is regenerated
