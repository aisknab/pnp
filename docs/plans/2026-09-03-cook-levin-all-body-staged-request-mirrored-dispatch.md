# M225: Cook-Levin all-body staged-request mirrored dispatch

## Selection rationale and legacy anchor

The pinned legacy manuscript's `TraceEquivalence` lemma and final SAT-decision
section require one uniform concrete Cook-Levin formula builder.  The active
reconstruction records that obligation under `Formal.ConcreteSAT` and the open
`reductions-complete-cook-levin-builder` checkpoint.

M224 connects only post-header coordinate zero, whose request is known to be the
first clause separator.  Extending another fixed coordinate would not retire an
unbounded dependency.  The next reusable edge is instead the whole clause-token
rectangle: every one of its arbitrarily many coordinates must carry one of the
five canonical optional-token requests through the physical classifier and into
the fixed reflected dispatcher.

## Unbounded abstraction and bounded theorem target

Define the body opportunity type as the finite rectangle

```text
Fin (problem.formulaClauseSlotCount * problem.formulaTokensPerClause).
```

Embed every such coordinate into the existing complete post-header controller.
For each coordinate, place the already-defined canonical optional-token request
in an explicit protected tape sidecar next to the current emitted prefix.  Build
one fixed relay machine, independent of the coordinate and request, that:

1. starts at the accepting terminal of M220's complete 711-rule classifier;
2. scans left across the complete blank-free classifier geometry;
3. crosses the protected sentinel and validates the tape-resident request as one
   of the five M217 request symbols; and
4. halts in exactly the spatially reflected M217 dispatcher configuration.

Compose that relay with M220 and M223's reflected 64-rule dispatcher.  Prove for
every body coordinate that the one fixed composition reaches the exact next
canonical emitted prefix, including padding coordinates, and retain exact work,
compiled execution, one-step-short nonhalting, collision freedom and one
source-input-size polynomial bound.

## Claim boundary and downstream blockers

The canonical request is staged on the initial tape by the theorem's
configuration definition.  M225 proves that one fixed literal machine preserves,
validates and physically dispatches that request; it does **not** prove that a raw
machine computes the request from the verifier input and coordinate.  That
request-synthesis edge remains load-bearing.

The unique `Finish` path remains covered by M223.  M225 does not combine the body
and `Finish` paths in one repeated machine, connect successive schedule
configurations, construct the request sidecar, prove complete builder
`FunctionProgram.RawRefinement`, package the Cook-Levin `PolynomialReduction`,
establish concrete NP-hardness or NP-completeness transport, put `CNFSAT` in
`P`, close a fixed checkpoint or global gate, create the eligible root theorem,
or prove `P = NP`.

The fixed risk-weighted score therefore remains 35 percent with the 20 to 40
percent uncertainty range.  Formal artefact coverage is regenerated separately.
